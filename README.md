## Design system

The idea: a working field manual on a desk next to the phone. Printed pages, ruled lines, pen notes in the margin. Members open the portal in dark graphite and can switch to light with the moon/sun button; the sales page opens in light paper. Both remember the choice in `localStorage` key `tcm_theme`.

- Styles: `client/src/styles/brand.css` holds tokens and shared components and is copied to the sales page. `client/src/styles/app.css` is the portal. `site-src/css/landing.css` is the sales page and tints the neutrals warmer.
- Portal dark: canvas `#141415`, rail `#0F0F10`, surface `#19191B`, text `#EDEDED`, secondary `#AEAEB3`, muted `#8A8A90`, pen `#8FB3EC`. Primary button is off-white.
- Portal light: canvas `#FAFAFA`, surface `#FFFFFF`, text `#171717`, secondary `#525252`, muted `#6F6F6F`, pen and primary `#143A73`.
- Sales page light: canvas `#F7F4EE`, surface `#FDFBF7`, text `#1F1B16`, pen and primary `#143A73`.
- Type: Schola (TeX Gyre) regular for titles and lesson reading, Heros (TeX Gyre) for everything you click. Bold is only for emphasis inside lesson text. Hierarchy comes from size and colour.
- Spacing sits on a 4px grid. Hover and press use one easing curve, `--ease`. Looping motion is kept only for live states (recording, saving).
- Signature: the margin note. A short pen-coloured note on the ruled margin, tied to its line by a hairline (`.turn .why`). Use it only to comment on what someone said.
- Moments: the annotated call, and the 30-day line (`.ruler`, `client/src/components/TrackLine.jsx`). Keep everything around them quiet: ruled lists rather than boxes, one pen colour, no accent bars or glows.
- The redesign used the [unslop](https://heydamir.design/unslop) method by Damir Sokolovsky (@heydamir), CC BY 4.0.

The name in the UI is The Cold Manual. Internal identifiers (the `OSI` namespace, `osi_` storage keys, cookie name, package folder) are unchanged so existing data keeps working.

## Run it

Needs Node 18+ and a MongoDB (Atlas free tier works).

```bash
npm run install:all
cp server/.env.example server/.env      # fill SESSION_SECRET, MONGODB_URI, ADMIN_EMAIL, ADMIN_PASSWORD
npm run build                           # content + sales page + React client
npm run seed                            # creates the admin account (safe to run again)
npm start                               # http://localhost:4000  (/ -> sales page, /app/ -> members)
```

Try it with no database: `npm --prefix server run dev:memory` (data is lost on restart).

Develop: `npm run dev:server` and `npm run dev:client` (Vite on 5173 proxies `/api` to 4000).

## Tests

- `npm test` runs 62 server tests on an in-memory database: accounts, sessions, codes, saving, content gating, roles, teams and seats, CSV, webhook, passwords, static files, skills, AI limits and AI safety, answer matching and the question review.
- `npm run test:e2e` is not wired to a script; the browser tests are `scripts/e2e.js` (146 checks; needs Playwright and a built client: `node scripts/e2e.js`; it launches Chromium with a fake microphone for the drills) and `scripts/e2e-tools.js` (connected tools, reply handler, Ask the manual, admin review and AI screens using the sample answers).
- `npm run test:db` runs the same database contract against MongoDB. Set `MONGODB_URI` first (use a scratch database).

## Deploy

One Node process serves the API, the app and the sales page. Render, Railway or Fly all work:
- Build command: `npm run install:all && npm run build`. Start command: `npm start`.
- Set the env vars from `server/.env.example`. `NODE_ENV=production` needs a 32+ character `SESSION_SECRET`.
- Behind a proxy or load balancer set `TRUST_PROXY=1`, so rate limits see real visitor IPs. Serve over HTTPS (cookies are secure in production).
- Run `npm run seed` once. Then sign in at `/app/` as the admin and disable `PREVIEW_CODE` before launch.

## Selling it

Access codes are the product key. Make them in Admin, or let your payment tool do it:

`POST /api/webhooks/payment` with header `x-webhook-secret: <WEBHOOK_SECRET>` and JSON:
- Individual: `{ "email": "a@b.com", "reference": "order-123" }` returns one single-use code.
- Team: `{ "plan": "team", "email": "boss@co.com", "orgName": "Acme", "seats": 10, "reference": "order-124" }` returns a join code and a manager code.

The same `reference` always returns the same codes, so retries are safe. Zapier or Make can call it from any checkout.

## Skill map rules

Edit `shared/skills.mjs`. Score = skill check x2 + roleplay x3 + lessons x1, averaged by what exists. Under 40 Learning, 40 to 69 Developing, 70 and over Strong. The lessons behind each skill are in `SKILL_LESSONS`; the 18 check questions are in `content-src/placement.js`.

## Changing content

Course content lives in `legacy/data/` and `legacy/code/`. Drills are in `legacy/data/extras-drills.js`, delivery templates in `legacy/data/extras-delivery.js`, Program 13 in `legacy/data/lessons-9.js`. After editing, run `npm run build`. ## Security notes

Passwords hashed with scrypt. Sessions are signed cookies (HttpOnly, SameSite) with revocation ("log out everywhere", password change). State-changing requests need a custom header. The microphone is allowed for this site only (Permissions-Policy `microphone=(self)`), and recordings play from `blob:` URLs (CSP `media-src`). Rate limits on login, sign-up and webhook. CSV export neutralises spreadsheet formulas. Team data is isolated per organisation. Get a legal review of your terms and privacy text before taking payments.

## Browser-only demo

`node demo/build.js` (after `npm run build`, with esbuild available) builds `demo/out/`: the real API code runs in the page against the in-memory database, with a sample team. It is for showing the product, not for selling: data resets on reload and the demo password hashing is not secure.
